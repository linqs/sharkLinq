# Architectural Adaptations for Fine-Tuning Domain-Specific Re-Identification Models

## 1. Introduction and Task Context
- The objective is fine-tuning vision foundation models for instance-level
  re-identification. While the primary application domain is shark
  re-identification, the architectural principles and adaptations discussed here
  generalize to any fine-grained, domain-specific visual matching task.
- Two distinct foundation backbones are utilized: a Vision Transformer (ViT) and
  MiewID (a CNN-based architecture).
- The models are adapted and evaluated under two distinct metric learning
  paradigms: Triplet Loss (distance-based contrastive learning) and ArcFace Loss
  (angular margin-based classification).

## 2. Foundation Model Backbones
- **Vision Transformer (ViT):** The ViT processes an image as a sequence of
  patches. Global semantic context is aggregated into a prepended Classification
  (CLS) token via self-attention mechanisms across the network layers. The
  output feature representation used for downstream tasks is the dense embedding
  of this CLS token.
- **MiewID (CNN-based):** MiewID employs hierarchical convolutional layers to
  extract spatial features. The final spatial feature maps are
  aggregated—typically using Global Average Pooling (GAP)—into a dense,
  high-dimensional feature vector.
- **Unification:** Despite the fundamentally differing extraction mechanisms
  (global attention versus hierarchical spatial pooling), both backbones
  ultimately produce a dense 1D feature representation that serves as the
  foundation for the subsequent metric learning adaptations.

## 3. Parameter-Efficient Fine-Tuning (PEFT)
- Adapting massive foundation models to niche domains risks catastrophic
  forgetting and incurs heavy computational overhead. To mitigate this, Low-Rank
  Adaptation (LoRA) is integrated into the training pipeline.
- **Backbone Adaptation:** LoRA layers are injected into the self-attention
  blocks of the ViT and the convolutional blocks of the MiewID backbone. The
  original pre-trained weights of the foundation models remain frozen, and only
  these low-rank matrices are updated during training.
- **Projection Head Training:** Unlike the parameter-efficient backbone, the
  task-specific projection heads (for both Triplet and ArcFace setups) are
  instantiated from scratch and remain fully trainable. This hybrid approach
  allows the model to map generalized visual features into a highly specialized
  metric space efficiently.

## 4. Architectural Adaptation for Triplet Loss
- **Concept:** Triplet loss explicitly optimizes the relative Euclidean distance
  between embeddings in a continuous space. It ensures that an anchor image is
  closer to a positive sample (same identity) than to a negative sample
  (different identity) by a predefined margin.
- **The Projection Head:** A Multi-Layer Perceptron (MLP) is added on top of the
  backbone. This head serves as a non-linear transformation layer, often used to
  reduce dimensionality and to map the raw backbone features into a dedicated
  metric space.
- **Training Architecture:** The backbone and the MLP projection head operate
  sequentially. The loss is computed on the final outputs of the MLP.
  Consequently, the entire sequence (the fully trained MLP and the LoRA-adapted
  backbone) is optimized to satisfy the triplet distance constraints.
- **Inference Architecture:** Because the triplet margin is strictly enforced on
  the *outputs* of the MLP during training, the true optimized metric space
  exists only after this transformation. Therefore, the MLP projection head is
  **kept** during evaluation and inference. The retrieval system relies on
  embeddings generated by the final layer of the MLP to ensure the learned
  relative distances are preserved.

## 5. Architectural Adaptation for ArcFace Loss
- **Concept:** ArcFace approaches metric learning by treating it as a closed-set
  classification problem during training. It enforces an additive angular margin
  penalty between an embedding and its ground truth class center on a
  hypersphere, promoting highly discriminative and angularly separated
  embeddings.
- **The Projection Head:** Instead of a transformative MLP, the projection head
  in the ArcFace setup is a specialized classification weight matrix. Each
  weight vector in this head represents a static "class center" for a specific
  identity present in the training dataset.
- **Training Architecture:** The model requires a specialized wrapper that
  receives both the image and its corresponding identity label during the
  forward pass. The backbone outputs a raw embedding, and the ArcFace head
  computes the angular similarity between this embedding and the learned class
  centers to calculate the margin-penalized classification loss.
- **Inference Architecture:** During evaluation, the ArcFace projection head
  (the classification weights) is **completely discarded**. Because the ArcFace
  loss function directly forces the backbone to push its raw outputs into a
  discriminative hypersphere, the backbone's L2-normalized output *is* the
  optimal embedding space. The system relies purely on the backbone to extract
  embeddings, which are then compared using simple similarity metrics (like
  cosine similarity) to identify unseen individuals.
